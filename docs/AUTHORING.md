# 新增一个数学讲解

## 先写清要解释什么

概念页选一个值得操作的变量和一个可观察的关系，如“常数项改变，根的个数何时改变”。题解页先保留完整题干，再定位“哪个条件使这一步可做”。不要先堆控件，再找教学理由。

例题的`source`必须说明自编或可再分发来源。原始试卷/学生材料默认置于仓库外；本版不含自动OCR与上传功能。

## 内容契约

在`src/content/catalog.ts`注册`Lesson`。`schemaVersion`当前为1；每篇有稳定id、类型、主题、前置知识、来源/许可、modelId、完整题干、中性studentTitle、方法路径、边界和复核状态。

每个方法有有序步骤：

```ts
{
 id: 'existence',
 title: '核对两个不同交点',
 why: '点差法只给出必要关系，还必须证明交点存在。',
 dependsOn: ['subtract'],
 body: [{type:'math', tex:'(y-2)^2=4(h-1)', display:true}],
 scenePatch: {h:1},
 highlight: ['tangent-point', 'secant']
}
```

- `why`解释动机；`body`写可核查的推理，不用图形替代证明。
- `dependsOn`只能引用本方法中先声明的步骤，防止环与悬空引用。跨方法比较写成完整新路径，不随意跨路径依赖。
- `scenePatch`只能使用模型注册的有限参数；`highlight`引用模型声明的对象id。有些对象只在有效状态存在，空集时不会画假的端点。
- 文本为纯文本，公式为KaTeX支持的LaTeX；不写HTML、JavaScript表达式、`eval`或外链脚本。
- review初始为draft。独立复核、实际视觉和边界核验通过后再改为reviewed，并记录证据。

## 数学模型

在`src/math/models.ts`注册可信`MathModel`。声明参数及显示范围、稳定对象id，纯函数`compute(state)`返回`Scene`。

`Scene`的viewport使用真实平面坐标；渲染器保持x/y相同尺度。读数、对象与有效性必须来自同一次计算。有限视窗不应改写数学定义域。对于失效/退化状态，先明确条件与含义，再决定画什么。例如h=1是切点，不能返回两个重复点并标成一条普通弦。

新模型应针对等价条件、逆向覆盖、零分母、符号、边界及极端值写有意义的性质测试；不只复制计算式测试自身。随机过程将来需显式种子，数值抽样不冒称为一般证明。

## 导出边界

教师页本来就含解法；默认站点是教学演示。学生导出通过`studentDocument()`白名单，使用不含解题提示的studentTitle，只保留题干/来源等允许字段，另生成静态HTML，不加载模型或教师目录。若为学生加入图形，必须另定义不泄题的安全场景，不从教师Scene删除一个图层就默认安全。

公开仓库可查到答案。学生文件不含答案是文件交付规则，并非限制学生访问公开代码。

## 提交前

1. 内容、LaTeX、参数与对象引用校验。
2. 独立核对一般证明、分类覆盖与教师用途。
3. 数学性质测试及实际交互。
4. 桌面、390px、键盘、深浅主题、退化/空集。
5. 全离线与真实学生导出检查。
6. 确认来源许可、无私有资料，再提交PR。
